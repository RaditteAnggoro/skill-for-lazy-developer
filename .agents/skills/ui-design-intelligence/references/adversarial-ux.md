# Adversarial UX review

Challenge the interface without treating every preference as a defect:

- Would a user need the same decision twice?
- Is a control duplicated or does it compete with the primary action?
- Does the empty or error state explain the next action?
- Is selection, unsaved state, or undo visible and recoverable?
- Does a dense financial table preserve totals, labels, and meaning without color alone?
- Does a validation message identify the field and the fix?
- Does the design add decoration that obscures the task?

Report a confirmed friction with route, viewport, step, impact, and suggested change.
State counterexamples: a confirmation may be necessary for an irreversible action; a
dense layout may be appropriate for expert reconciliation. Do not flatten important
safety friction into “cleaner UI”.
