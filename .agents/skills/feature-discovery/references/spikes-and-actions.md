# Spikes and document action extraction

## Spike eligibility

Choose a spike when the answer to one technical question changes the implementation
choice and a small experiment provides better evidence than discussion. Use an isolated
fixture, state prohibited side effects, record the result, and remove disposable work
unless the user requested preservation.

## Document actions

When extracting actions from notes or source documents, preserve:

`source_id`, exact content or faithful summary, `decision_status`, `requested_action`,
`owner_if_named`, dependency, evidence link, open question, and acceptance condition.

Never invent owners, dates, approvals, or requirements. Merge duplicates only when each
original source remains traceable. Distinguish agreed scope from meeting notes and
vendor claims. Do not silently read unrelated connected files.
